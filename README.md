# singularity-lean

The Lean 4 code of the singularity project. The project states resolution of singularities in characteristic $p > 0$ in Lean, formalizes the known cases, and works on the open case: varieties of dimension 4 and higher.

**The open case is not proved.** This package has the statements of the open problem and the first fidelity checks of the statements. It does not have a proof of the open case.

The map of the project, the milestones and the site are in [tamnd/singularity](https://github.com/tamnd/singularity). The site is [singularity.tamnd.com](https://singularity.tamnd.com). The `sing` command that reads the records of this package is in [tamnd/singularity-agent](https://github.com/tamnd/singularity-agent).

## What is here

| File | Content |
|---|---|
| `Singularity/Statements/Basic.lean` | the vocabulary: `regularLocus`, `IsRegularScheme`, `IsResolution` and `IsVariety` |
| `Singularity/Statements/Main.lean` | `ResolutionInDim`, `ResolutionOfSingularities` and `ResolutionDimFourCharP` |
| `Singularity/Statements/Core.lean` | the purely inseparable hypersurfaces $z^p + g = 0$, the core case of route R5 |
| `Singularity/Fidelity/Positive.lean` | check F2: the identity of a regular scheme is a resolution |
| `Singularity/Fidelity/Negative.lean` | check F3: the codiagonal $X \sqcup X \to X$ is not a resolution |
| `Singularity/Fidelity/Core.lean` | the core problem P1 is a special case of the main statement |
| `Singularity/Algebra/Regular.lean` | regular local rings: the quotient by a parameter, a regular local ring is a domain, and in dimension 1 regular is the same as integrally closed |
| `Singularity/Algebra/Normalization.lean` | the integral closure of a domain is finite over it, when its fraction field is separable over a Noetherian normal subring, and for each finitely generated domain in characteristic 0 |
| `Singularity/Scheme/NormalDimOne.lean` | a locally Noetherian scheme of dimension at most 1 with integrally closed local domains is regular |
| `Singularity/Algebra/NormalizationCharP.lean` | the normalization of a domain that is a finitely generated algebra over a field is finite, in each characteristic (E. Noether) |
| `Singularity/Curves/Affine.lean` | the normalization of an affine curve over a field is a Dedekind domain, so it is a regular ring |
| `Singularity/Algebra/NormalLocus.lean` | the normal locus of a domain with a finite normalization is open: the conductor argument |
| `Singularity/Algebra/HilbertSamuel.lean` | the Hilbert-Samuel function $n \mapsto \ell(M/I^n M)$ with its laws and its finiteness, and the order of an element with its laws |
| `Singularity/Algebra/RegularSequence.lean` | the maximal ideal of a regular local ring is generated by a regular sequence of length $\dim R$, and the residue field has projective dimension $\dim R$ |
| `Singularity/Algebra/ExtCriterion.lean` | over a Noetherian local ring, a finite module $M$ has $\operatorname{pd} M \le n$ if and only if $\operatorname{Ext}^{n+1}(M, k) = 0$ |
| `Singularity/Algebra/GlobalDimension.lean` | over a regular local ring $R$, each finite module has projective dimension at most $\dim R$ |
| `Singularity/Scheme/Components.lean` | the irreducible components of a reduced Noetherian scheme: each component is integral, and a point with a domain as local ring lies on one component only |
| `Singularity/Scheme/Reduction.lean` | `reductionToIntegral`: the proof of `ReductionToIntegral`, and the lemma that a finite disjoint union of proper maps is proper |
| `Singularity/Curves/Resolution.lean` | `integralResolutionInDim_one` and `resolutionInDim_one`: each curve over a field of each characteristic has a resolution |
| `Singularity/Known/DimZero.lean` | `resolutionInDim_dim_zero`, resolution in dimension 0 in each characteristic |
| `Singularity/Hypotheses/Integral.lean` | `IntegralResolutionInDim` and the statement `ReductionToIntegral` |
| `Singularity/Bridge/FormalConjectures.lean` | the statements of google-deepmind/formal-conjectures, copied as propositions |
| `base/SingularityBase/Bridge.lean` | the bridge: the statement of the project implies the statement of formal-conjectures |
| `base/SingularityBase/CharZero.lean` | `integralResolutionInDim_zero` and `resolutionInDim_charZero`, characteristic 0 from resolutionorg/hironaka |
| `scripts/Export.lean` | writes the record of the build: each declaration, its type and its axioms |

The statements use "regular" and not "smooth over $k$". Over an imperfect field a regular variety need not be smooth, so the statement with "smooth" is false there.

## Build

The package uses Lean `v4.35.0` and Mathlib `v4.35.0`. This is the pin of resolutionorg/hironaka, the base of the project in characteristic 0.

```sh
lake exe cache get
lake build
```

To write the record of the build:

```sh
lake env lean --run scripts/Export.lean "$(git rev-parse HEAD)" v4.35.0 "$(date -u +%Y-%m-%d)" > records/lean.json
python3 scripts/axioms.py records/lean.json
```

## The base package

The directory `base/` is a second Lake package, `SingularityBase`. It depends on this package and on resolutionorg/hironaka at the commit in `manifests/base.yaml`. The base has about 630 files in the import closure that this package uses, so the first build takes a long time. The workflow `base` builds it and keeps the build in an actions cache.

```sh
cd base
lake exe cache get
lake build SingularityBase
lake env lean --run ../scripts/Export.lean "$(git rev-parse HEAD)" v4.35.0 "$(date -u +%Y-%m-%d)" SingularityBase > ../records/base-charzero.json
```

The base proves Main Theorem I for integral varieties only. The step to reduced varieties is `Singularity.Reduction.reductionToIntegral` in the main package. Thus `resolutionInDim_charZero` gives `ResolutionInDim 0 n` for each `n` with no hypothesis.

## Rules

1. No `sorry`, `admit`, `axiom` or `native_decide` in the main tree. Work that is not finished goes in `Singularity/WIP/`, which `Singularity.lean` does not import. The script `scripts/scan.sh` checks this.
2. A published theorem that is not formalized yet is a `def ... : Prop` and a hypothesis of the theorems that use it. It is never an `axiom`.
3. The files of `Singularity/Statements/` are pinned by hash in `manifests/statements.sha256`. A change to a statement must change the hash in the same pull request.
